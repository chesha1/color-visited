## 现在的问题

截图是用构建产物在 headless Chrome 里截的，字体换成了 Segoe UI 和微软雅黑，接近 Windows 上的样子。单个控件都还行，丑是下面几件事叠在一起：

1. **三套风格混在一起。**
   - Element Plus 默认的后台风格：左侧 tab 文字右对齐、配一条蓝色竖线，el-form 右对齐的标签列，el-card，el-alert。
   - Tailwind 写的装饰：预设网站顶部蓝到紫的渐变卡片，带阴影的大圆角卡片，绿点、紫点和彩色胶囊标签，原生 `<button>` 做的"全部启用""全部禁用"。
   - 颜色有 Element Plus 的蓝、green-600、purple-500。灰色也有两套：Tailwind 偏蓝的 gray-900、gray-600，Element Plus 的 #303133、#606266。
2. **同一个标题出现三次。** 对话框标题"设置"、左侧"常规设置"、内容区又一个 18px 的"常规设置"，再加副标题和分隔线。这条分隔线是对话框里最重的线：Tailwind v4 的 `border-b` 不写颜色时用 currentColor（v3 默认是 gray-200），实测是 #606266 的深灰。
3. **四个 tab 是四种布局。**
   - 常规、快捷键是 el-form，标签在左列；同步是标签在上、开关在最右；预设网站是卡片。
   - 控件有 large（40px）和 default（32px）两种尺寸：40px 的取色块挨着 32px 的输入框；底部按钮是 large，同步页的按钮是 default。
   - el-form 的标签按 32px 行高排，旁边 40px 的控件中线比标签低 4px。
4. **高度没分配好。** 内容区固定 400px。常规、快捷键两页下半截是空的；同步页内容 570px 高，"同步状态"和"测试连接""立即同步"要滚动才看得到。
5. **预设网站太稀。**
   - 每个站点一张约 92px 高的卡片，名字 18px 加粗，和页面标题一样大；副标题"5 种生效范围 · 2 种可染色链接"对用户没什么用。
   - 32 个站点，滚动高度 3415px，一屏只看得到两个半。
   - 展开后是卡片套卡片再套方框；规则列表最高 128px，还有自己的滚动条。
6. **快捷键页。** 快捷键显示在一个 523px 宽的只读输入框里，看着像能编辑；下面一条灰色 el-alert"请按下您想要使用的快捷键组合..."，像系统提示。
7. **同步页。** 为了一行"最后同步时间:"（还是半角冒号）用了整张 el-card。"测试连接"是 primary，滚到底时和"保存设置"两个主按钮同时出现。
8. **窄窗口会溢出。** 宽度写死 900px，Element Plus 的对话框没有 max-width。窗口不到 900px 宽（比如 1366 宽的笔记本分屏）时横向溢出，关闭按钮和"保存设置"都跑到屏幕外。
9. **小地方。** 取色面板里的"Clear""OK"是英文，因为没给 Element Plus 设中文 locale；对话框圆角只有 4px。

## 方向

用回 Element Plus 自己的样式，所有 tab 用同一种"设置行"。

- **颜色只用 Element Plus 的变量。** 主色只有一个蓝；文字、边框、底色取 `--el-text-color-*`、`--el-border-color-*`、`--el-fill-color-*`，Tailwind 4 可以直接写 `text-(--el-text-color-secondary)`。不再用 Tailwind 的调色板（gray、green、purple、blue）。
- **Tailwind 只管布局和间距。** 不再写渐变、彩色小标签、阴影卡片。
- **控件统一用 default 尺寸**，底部按钮也一样。
- **设置行。** 每一项占一行，左边是标题加一行灰色说明，右边是控件。一页的行放在一个浅色边框的圆角框里，行之间一条浅色分隔线。Chrome、GitHub 的设置页都是这样。
- **内容区不再重复 tab 名。** 去掉每页顶部的大标题、副标题和分隔线。
- **边框都写颜色。** Tailwind v4 的 `border`、`divide` 不写颜色时是 currentColor，问题 2 里那条深色线就是这么来的。

## 已定的决策

### D15 · 外框：tab 放顶部

考虑过两种：

- **A：tab 放顶部，对话框收窄到约 680px。**
- **B：保留左侧栏，改成 Slack、Notion 那样**：文字左对齐、选中项整块浅色底、没有竖线，宽度 720～760px。

2026-10-30 定了 A。理由：

- 规范没有统一的答案，看 tab 有几个、以后会不会变多。
  - 微软的 Windows 导航规范：想把所有选项都摆在屏幕上、给内容留更多空间时用顶部导航；选项超过 5 个、用户不常切换时用左侧导航。
  - NN/g《Tabs, Used Right》（2024）：页面内的 tab 列表放在内容上方，竖排容易被忽略；标签最好一两个词。
  - NN/g《Left-Side Vertical Navigation on Desktop》（2021，讲的是网站导航）：以后还会加分类时，左侧竖排更合适，竖着的列表也更好扫读；缺点是占地方。
  - Apple HIG：macOS 的设置窗口通常是顶部一排工具栏按钮。
  - 实际产品里，设置弹窗用左侧栏的更多（Slack、Notion、ChatGPT、Obsidian、Word 的"选项"），这些产品的设置分类大多在 8 个以上。放顶部的例子有 Tampermonkey 和 uBlock Origin 的管理面板、Gmail 的设置、macOS 应用的设置窗口。
- 我们只有 4 个 tab，标签短，顶部放得下，内容区也更宽。直接用 Element Plus 默认的顶部 tab，不用覆盖它的样式；B 要覆盖五六条。
- 现在的左侧栏难看，是 Element Plus 默认样式的问题，和放在左边无关。以后 tab 多到顶部放不下（超过五六个），再换成 B。

S25 已把 B 写进 AGENTS.md「已经定了的取舍」，免得以后再提。

### D17 · 提示没保存的修改

2026-10-30 定了：做。

- 现在点 ✕ 会直接丢掉修改，没有任何提示。丢掉修改是有意的设计（见 AGENTS.md「对话框只有一份 draft、一个保存」），缺的是让人看得出还有没保存的修改。
- 有改动的 tab，标签后面加一个主色小圆点；底部"保存"左边加一行灰字"有未保存的修改"。
- 两处都看 `changes`（`diffSettings` 已经按分组算好了）：圆点看这个 tab 的分组在不在里面；灰字和"保存"能不能点，是同一个条件。
- 圆点用 el-tab-pane 的 `label` 插槽，`#tab-…` 的 id 不变。
- 快捷键页不再自己提示"已修改"：按下新组合键时键帽马上变，tab 上的圆点和底部的灰字已经说明还没保存。ShortcutTab 的 `changed` 属性随之去掉。同步页的 `changed` 要留着，它决定"立即同步"能不能点。
- 不做关闭前的确认框：那是行为上的变化，要做的话单独提。

## 设计

线框图里的文字就是 D18 定下的文案。框只画了左边，因为中文在等宽字体里对不齐右边框。

### 外框

- tab 放顶部，用 Element Plus 默认的样式。
- 宽度写成 `min(680px, 100vw - 32px)`，窗口窄时跟着收，不再横向溢出。el-dialog 的 `width` 接受字符串，会原样写进 `--el-dialog-width`。
- 内容区高度固定，大概 400px，切 tab 时对话框不跳；窗口矮时跟着视口收，内容区自己滚动。
- 加 `align-center`，垂直居中。Element Plus 的做法是给遮罩加 flex、给对话框加 `margin: auto`，对话框比窗口高时，顶部不会被顶出去。
- 标题用 el-dialog 的 `title` 属性，不再自己写 header 插槽。
- 圆角 8px，和内容区里的圆角框一致。
- 底部：左边一个文字按钮"恢复本页默认值"，右边主按钮"保存"，都用 default 尺寸。现在的"重置为默认"其实只重置当前 tab，名字要说清楚。
- 未保存提示（D17）：有改动的 tab，标签后面一个主色小圆点；"保存"左边一行灰字"有未保存的修改"。
- 给 Element Plus 设中文 locale，取色面板里的按钮就变成"清空""确定"。
- 内容区的滚动条用 `scrollbar-width: thin`，细一点。

### 设置行（新文件 ui/SettingRow.vue）

- 左边：标题 14px，用主文字色；说明 12px，用次要文字色。说明是插槽，可以放链接。
